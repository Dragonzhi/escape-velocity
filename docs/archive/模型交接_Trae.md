## 0. 这次要交付什么（一句话）

把现有的行星/太阳/探测器模型**从"低模色块"升级到"像坎巴拉太空计划那样的观感"**，
并且**补齐 UV**（现有模型连 UV 都没有，所以任何贴图都贴不上去）。

## 1. 引擎与它的硬边界（先读，能省掉大量白工）

- 引擎：**Dora SSR 1.9.3.6**，通过 Model3D(路径) 加载 **glTF 2.0（.glb 或 .gltf）**，文件放在 Assets/Model/。
- **没有后处理管线**：没有 bloom、景深、运动模糊、色调映射。所有"发光"效果靠**自发光贴图 + 面向相机的面片**伪造（我们已经给太阳做了）。
- **没有自定义着色器**：只能用 glTF 的标准 PBR 槽位。引擎侧逐实例可设置的只有：
  baseColor（含 alpha）、emissive、metallic、roughness、alphaMode（Opaque/Mask/Blend）、alphaCutoff，
  以及贴图槽：baseColorTexture / emissiveTexture / metallicRoughnessTexture / normalTexture / occlusionTexture。
- **引擎拿不到 glTF 里的子节点**：节点的 children/名字**不可寻址**。所以**任何需要独立运动的部件，必须拆成单独的文件**
  （这正是探测器被拆成"机体 + 天线"两个文件的原因）。
- **引擎会把整个模型缩放**：游戏里 行星半径 = displayRadius（世界单位），引擎用 scale = displayRadius / k 来缩放，
  其中 k 是我们标定出的"该模型在 scale=1 时的外接半径"。**因此模型必须是单位尺寸、原点在几何中心**（见 §3）。
- 包体预算：整个游戏（含 Web 导出）目前约 17 MB，目标压到 8 MB 量级。**模型与贴图要克制**（见 §3 预算）。
- 已知实测：外部 PNG 贴图可以加载（Texture2D('Assets/Image/xxx.png') 已在用）。
  ⚠️ **glb 内嵌贴图尚未验证过**（现有模型一张贴图都没有）。两条路：
  ① **推荐**：模型只交付**几何 + UV**，贴图放外部 PNG（我来生成/绑定）；
  ② 如果你要内嵌进 .glb：请先只做一个最小样例（一个带内嵌贴图的球）通知我们，我们跑一次引擎验证再继续。

## 2. 我们这边会做的事 —— **你不必做**

| 你**不要**做的事 | 原因 |
|---|---|
| 不要烘焙光照、不要画明暗交界线 | 引擎里有真实光源（一盏方向光），行星的晨昏线是算出来的 |
| 不要做光晕、镜头光斑、辉光 | 靠面向相机的**自发光面片**伪造（太阳已经有了） |
| 不要做轨道圈、星空 | 由仓库内脚本生成（OrbitRing_*.gltf / StarSphere.gltf） |
| 不要为"大小"建模（比如把木星做成土星的 5 倍） | 引擎按真实压缩比例缩放，模型必须都是**单位半径** |
| 不要做 LOD、不要做动画/GIF、不要做骨骼 | 引擎不使用；探测器只有"天线指向地球"这一个绕轴旋转 |
| 不要给行星"上色"当最终颜色 | 引擎会逐实例覆盖 baseColor（关卡数据决定颜色与自发光）。**但探测器例外：探测器的材质与贴图由你决定，我们不改** |
| 不要做太阳的日冕几何 | 光晕用面片做；你只需要给太阳本体**表面**（黑子、米粒组织、暗边） |

## 3. 必须由你在模型里预设好的事（做错了就得返工）

### 3.1 尺寸与原点
- **球体：半径 = 1.0，球心在原点**（不是直径 1、不是 2）。导出前用 Blender 的"半径 1"建立球体，
  缩放应用（Ctrl+A → Scale）后再导出，避免 scale 留在物体变换里。
- **探测器：以最长轴为准，整体落在 ±1.0 以内**，原点放在**重心**（不需要单位半径，但要能被 scale 缩放而不跑位）。
- **绕轴旋转的部件（天线）：原点必须落在它的转轴上**（现有约定：天线文件按"转轴 = 文件原点"导出）。

### 3.2 UV（本次最重要的一条）
- 现有模型**全部没有 UV**（顶点属性只有 NORMAL, POSITION）⇒ 贴图无法显示。
- **所有要贴图的对象都必须有 UV**：球体用等距圆柱（equirectangular）展开：
  U 沿经度 0..1 环绕（接缝放在背面），V 沿纬度 0..1（两极分别 0/1）。
  建议经度 64 段、纬度 32 段（≈4k 三角面）——这个密度在手机屏幕上已经看不出多边形。
- 环（土星/天王星）：UV 用**径向**展开（U 沿半径，V 沿圆周），贴图是一张 1×N 的条带（含缝隙与透明度）。

### 3.3 朝向约定（**改动会造成朝向错乱，务必保持**）
- 引擎的 angleY 把**局部 +X** 旋到世界方向；探测器用 ProbeYawOffsetDeg = -90 做补正。
- **现有 Voyager 探测器的体轴**：两根粗主杆沿 **+Z**、一根细长磁强计杆沿 **-Z**；
  游戏里让 **-Z（细杆）朝前**。**新的探测器模型请沿用同一朝向**（两根主杆朝 +Z）。
- **天线**：转轴在文件原点，**静止（angleY=0）时碟面法线指向局部 +X**。
  如果新模型朝向不同，请在交付说明里写明，我们会重新标定（有两个常量：ProbeYawOffsetDeg、AntennaPivotY）。

### 3.4 土星/天王星环的平面（实测约定）
- **土星环在 xz 平面**（法线 = y = 世界"上"），环延伸到 ±2.2（半径 2.2），本体半径 1.0。
- **天王星环在 xy 平面**（法线 = z，对应真实 98° 轴倾），环延伸到 ±1.95。
- 环的材质**必须双面（doubleSided）**，alphaMode 用 Blend（有缝隙/透明）。
- 环**不参与** k 标定（k 只取本体半径），所以环做多大都行，但请保持上面的比例。

### 3.5 命名与拆分（引擎按文件名加载，必须精确）
- 行星：Assets/Model/Planet_Earth.glb、Planet_Venus.glb、Planet_Jupiter.glb、Planet_Saturn.glb、
  Planet_Uranus.glb、Planet_Neptune.glb，**新增 Moon.glb**（月球，本作第一关的目标）。
- 太阳：Sun.glb。
- 探测器（**两个版本，因为太阳能板在远处没用**）：
  - 近处（月球 / 金星 / 木星）= **Probe_Solar_Body.glb + Probe_Solar_Antenna.glb**（带太阳能板）
  - 远处（土星 / 天王星 / 海王星）= **Probe_RTG_Body.glb + Probe_RTG_Antenna.glb**（核电池 RTG，无太阳能板）
  每个版本都是"机体 + 天线"两个文件（原因见 §1：子节点不可寻址）。
- 旧文件请保留不要覆盖（Probe_Body.glb / Probe_Antenna.glb / Probe_Voyager_v1.glb 是我们的回退）。

### 3.6 面数与贴图预算（手机 + Web 导出）

| 资产 | 三角面 | 贴图 |
|---|---|---|
| 行星（含月球） | 4k~8k | 1024² （地球可用 2048²；含一张 emissive 做夜面灯光，可选） |
| 太阳 | 8k | 1024²（表面细节；光晕由我们做） |
| 探测器（每个版本，机体+天线合计） | 5k~12k | 1024² |
| 环 | 2k | 512×N 条带 |

- 导出为 **.glb（glTF 2.0 binary）**，勾选 **+Y Up**、应用变换、三角化（不要留四边形/NGON）。
- 贴图：PNG 或 JPG 都行；**文件名全小写、下划线**（planet_earth.png 之类），放 Assets/Image/。
- 不要内嵌相机、灯光、空物体（除了天线转轴那个必要对象）。

## 5. 交付前自检（你在 Blender 里就能验完）

1. 选中每个对象：**三角面数**在预算内（属性面板 → 统计信息）；
2. **UV**：物体有 UV 且无重叠（UV 编辑器里能看出等距圆柱展开）；
3. **尺寸**：球体外接半径正好 1.0（N 面板看尺寸 = 2.0 × 2.0 × 2.0 的立方体包围），原点在 (0,0,0)；
4. **变换已应用**（Location/Rotation/Scale 都是 0/0/1，环与天线的旋转除外）；
5. **命名**与 §3.5 完全一致（大小写敏感）；
6. **重新导入一次 .glb** 检查没有丢材质/丢 UV；
7. 交付时附一张**清单**：文件名 / 三角面数 / 贴图尺寸 / 是否有环 / 朝向说明（若与 §3.3 不同）。
