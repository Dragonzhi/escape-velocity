## 1. 病根：KeplerK 和太阳引力对不上，差 42.7 倍

`game/LevelData.ts` 里 `SunGm = 72000` ⇒ 圆轨速度 `sqrt(72000/80) = 30`、周期应为
`2π·sqrt(80³/72000) = 16.76s`；但 `KeplerK = 1.0` 让行星周期走 `r^1.5 = 715s`——**慢了 42.7 倍**。

也就是说：**行星并不是被太阳引力带着走的，而是被一条手设公式推着走的**，速度与太阳的真实引力毫不相干。
探测器飞的是真引力，行星走的是假运动，两者永远对不上。

L1 探测器默认坠日、引力弹弓能量收益只有 ~4%、关卡相位必须靠 `level-phases.mjs` 硬解、
「探测器绕地球」在动力学上不可能稳定——全是这一个根结的果。

## 2. 归正口径：一套缩放，其余全部导出

保留两个锚点（它们决定手感，且本身就是正确的缩放值）：

| 锚点 | 值 | 导出 |
|---|---|---|
| 1 AU = 80 单位（地球轨道） | 长度尺度 | **L = 1.496e8 / 80 = 1.870e6 km/单位** |
| v_circ(80) = 30 单位/秒 | 速度尺度（发射速度 5–55 的设计中心） | 时间尺度 **τ = 1.883e6 真实秒/游戏秒**，**1 游戏年 = 16.76 游戏秒** |

由此得到两条换算：

```
gm_game = gm_real × 5.425e-7
R_game  = R_real / 1.870e6
T       = 2π·sqrt(a³ / μ)          （不再有 KeplerK）
```

**自检（两条都对上，说明口径正确）**：

- 月球周期 = 1.259s ⇒ 每年绕地球 **13.3 圈**（真实 13.4）✓
- 木星引力弹弓偏转（b=20, v=30）= **13.1°**（现在是 μ=2500 算出的 475°，物理上荒谬）✓

## 4. 分阶段实施

### 阶段 0 —— 按钮防抖时钟（与重构无关，但必须先修）

**病根**：`game/Ui.ts` 的 `fireTap()` 用 `App.elapsedTime` 做 0.5s 防抖，而引擎里
`App.elapsedTime` 恒为 ~0.0001（实测 12 帧不动、`deltaTime` 正常）⇒ **每个按钮一辈子只能按一次**。
用户反馈的「发射 / 重试 / 返回点第二次没反应」全部源于此。

**改动**：`Ui.ts` 加模块级 `uiClock`，由 `Hud.update(dt)`（`init.ts` 已每帧调用）累加；
`fireTap()` 改用 `uiClock`。
**验证**：`pwsh tools/level-play.ps1 -Level 1 -TapX 519 -TapY 252 -Taps 3` ⇒ 日志 3 行
`view toggle fire` + `view ->` 交替。

## 5. 风险

1. **规模**：动到 `Config / LevelData / Game / CameraRig / PlanView / Hud / Scene` +
   六个测试模块 + 三个扫掠工具的镜像公式。截止 9-29 23:59，
   **任何一步失败超过 3 次就提交当前可用状态并如实记录**。
2. **观感**：归正后宽视角里天体是点（木星 0.0374 单位 @105 单位 ⇒ 约 0.5px），
   只有掠过近景（相机贴到 0.22 单位）才好看。这是真实尺度的必然结果，需用户确认接受。
3. **L1 节奏**：探测器 2.3 圈/秒。瞄准时时间会冻结（现有 S3.9.4 机制），
   但两次操作之间它跑得很快。
4. **太阳从 28 缩到 0.372**：用户此前明确要求过太阳大（比例尺参考图）。
   归正后它在 80 单位外是 6px 的亮点，符合「较远的地方可以看到一个发光的太阳」，但不再是画面主体。
