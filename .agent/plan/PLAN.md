1. **只有会动的行星能真正加速探测器**（静止引力源只改方向、不加能量，能量守恒）——

##### S3.6.3 三星评价（0.5 天）

- **判定（纯函数，可单测）**：`StarResult { mission, precision, speed }`
  - 任务 ★ = `ResultKind === 'success'`
  - 精度 ★ = 与「关键天体」的最近距离 ≤ `stars.precisionDist`（关键天体默认取目标；可用 `focusIndex` 改成飞掠体）
  - 速度 ★ = 末速度 ≥ `stars.minSpeed`
- **数据**：`LevelDef.stars?: { precisionDist: number; minSpeed: number; focusIndex?: number }`（缺省 = 该关只算任务星）。
- **接入点**：`Game.ts` 飞行结束时（`flight.points` 已按每步采样 ⇒ 逐点算与关键天体的距离；末速度取 `flight.state.vel`）。
- **存档（关键，必须向后兼容）**：`Progress` 扩成 `{ unlocked: number; stars?: number[] }`，文件两行：
  ```
  unlocked=3
  stars=3,2,0,1,0,0
  ```
  - 旧档没有 `stars` 行 ⇒ 全 0，**不整份作废**；解析失败同样归 0。
  - `stars` 保持**可选**字段 ⇒ 现有 `saveProgress({ unlocked: 3 })` 调用与 `ProgressTest` 的格式断言不用改。
  - 每次结算取 `max(旧星, 新星)`（与解锁一样“只增不减”）。
- **UI**：结算面板加一行三颗星（暗/亮）+ 三行小字（显示**原始数值**：最近距离、末速度 —— 玩家要知道差多少）；
  选关面板按钮上显示已得星数（`★★☆`）。
- **验收判据**：① 单测：判定纯函数（构造三种结果）+ 存档往返 + **旧档兼容**（只有 `unlocked` 行时读成 0 星）；
  ② 截图：三种星级各一张 + 选关显示星数；③ 日志：`stars=...` 落盘。

- **验收判据**：① 单测：同一初速度、不同 `t0` ⇒ 轨迹不同；同一 `t0` ⇒ 预测线与真实飞行逐点一致；

#### S3.7 · 关卡重构：宏大尺度 + 太阳主导 + 真实编年（2026-09-26 与用户定稿）

> **用户反馈**（原话摘要）："现在的关卡内容太奇怪诡异了，完全不知所云"、"视角拉宏大一点、星球之间的轨迹远一点、
> 完全没有宇宙的感觉"、"行星的运动完全不符合现实"。**优先级：先把关卡定清楚，再做幽灵轨迹等视觉优化。**
> 三个选择（用户已点选）：① 尺度 **宏大（距离 ×2.5）**；② **太阳主导的弧线 + 行星几乎不动 + 日期滑杆**；
> ③ **真实编年**（离开地球 → 金星修正 → 木星弹弓 → 土星窗口 → 大巡游 → 星际空间）。

**诊断（我认下的三条）**：① 一关只有 50–60 单位深、行星半径 1–3.5 ⇒ 是"桌上摆件"不是宇宙；
② 行星 5–12 秒公转一圈、圆心还是屏幕中间的空气（不是太阳）⇒ 不像太阳系，预测线像赌博；
③ 目标是"进入一个看不见的半径 6.31 的球"，简报只讲机制不讲故事 ⇒ 玩家不知道该往哪飞。

**改法（对应四条）**：

1. **太阳进物理**：每关（L1 除外）原点放太阳 `gm = SunGm`，行星改成**绕太阳同向公转**。
   探测器从此飞的是**绕日弧线**：向内飞被加速、向外飞被减速（真实的能量来源），掠过行星是**改向**。
2. **尺度 ×2.5**：行星轨道半径 55 / 80 / 105 / 135 / 165 / 195（"压缩太阳系"：**顺序与开普勒比例真实**，
   绝对半径压缩），行星半径 ×1.3（木星 4.63 / 土星 4.3 / … / 月球 1.0）；发射速度 2–22 → **5–55**；
   相机夹紧 25–100 → **60–260**。轨迹形状与飞行时间在"距离 ×S、速度 ×S、gm ×S²"下不变。
3. **开普勒 + 时间压缩**：`T = KeplerK · r^1.5`（相对快慢 = 真实开普勒；`KeplerK = 1` 相当于把真实速率
   除以 42.7）。效果：飞行 15 秒里，金星挪 ~13°、木星 ~5°、海王星 ~2° —— **看得见但不乱**；
   想看它动就拖**日期滑杆**（`timeWindow.span` 以秒为单位，拖一遍能让木星走完一整圈）。
   ⚠️ 代价要讲清楚：行星慢了 ⇒ 引力弹弓的**能量收益变小**（≤7%），它主要变成**改向**；
   真正的速度变化来自太阳（向内加速 / 向外减速）。文案必须这么写，不能骗人。
4. **目标画出来**：目标行星外套一圈**虚线容差环**（每帧重投影，俯视下是椭圆）；关间简报改成

#### S3.9 · 玩法闭环：出发在轨道上、推力剖面、进入轨道（2026-09-26 用户口述设计）

> **用户原话要点**：① 参考图是示意图，真实比例**按现实比例缩放**即可；② 灰色圆圈 = 行星轨道（行星要动，
> 得有轨道指示，不起眼的灰就行）；③ 白色方框 = 手机屏幕 —— 小的是关卡一开始（默认取景），
> 然后**逐渐拉到大的框，告知玩家目标地**（例：去木星）；④ **飞行器一开始就在运动，围绕地球**；
> ⑤ 是否加一个月球做教学；⑥ **拖动力度 = 决定加速与减速过程**：预测虚线前半段加速、后半段减速，
> 后半段减速时就能尝试**进入某颗行星的轨道**；⑦ 一个小按钮切换「全程加速靠惯性滑行 / 前半程加速后半程减速」。

##### S3.9.1 为什么这个想法是对的（我的判断）

- 它补上了现在最缺的一环：**"到了"是什么意思**。现在"到达"= 进一个看不见的容差球；改成"**减速到能进轨道**"之后，
  目标、过程、失败原因全都自洽了 —— 玩家能说出"我太快了，冲过去了"。
- 它给预测线**加了可读的物理含义**：线的斜率 = 速度。前半段变陡（加速）、后半段变平（刹车），
  玩家看得见自己在干什么 —— 这比"猜一个初速度"高一个层次。
- 它让开场镜头**有东西可讲**：从贴着探测器的近景（正在绕地球）拉到能看见目标行星的大框，
  一镜说完"你在哪、你要去哪"。
- 它把玩法从"一次性瞄准"变成"**调一个过程**"，而拖拽本来就是连续的 —— 输入方式与玩法对上了。

##### S3.9.2 落地方案（我的具体化）

##### S3.9.2a 捕获入轨（已落地，2026-09-26）

- `WaypointSpec.capture / captureFactor`：进环**且**相对行星的速度 ≤ `captureFactor ×` 该处圆轨道速度 ⇒ 入轨。
  **默认系数 √2**，也就是**逃逸速度** —— "相对速度低于逃逸速度 ⇒ 真的被这颗行星束缚住"，这才是捕获的物理定义；
  比原计划写的 1.0（圆轨道速度）更宽松，也正好是用户选的"先让人成功"那一档。
- `SimResult.velocities`（与 `points` 一一对应）：判据要的是"**相对**行星的速度"，只有位置没法算。
  ⚠️ 踩坑记：一开始用"相邻采样点差分"估速度 —— 撞毁时推演在那一帧**截断**，最后一点只跨半步 ⇒
  速度被低估，把"一头撞进行星"判成了**成功入轨**（实测 rel=34.7 vs 阈值 43.1）。两处修：① 模拟直接给出速度序列；
  ② 判据排掉本体半径以内（撞上去不叫入轨）。**这条如果没抓出来，就是玩家"撞毁了却显示成功"**。
- 设计上也做了一次拆分：**L3「弹弓」不做捕获**（它的新决策是方向性/加速，再叠"减速入轨"就是两件事），
  捕获从 **L4「窗口」**开始 —— 而它正是"选对日期才慢得下来"的那一关，机制与关卡意图配套。

##### S3.9.2b Δv 预算（2026-09-26 用户要求："避免力大砖飞，完全不顾及引力弹弓"）

- **数据**：`LevelDef.dvBudget`（每关给多少 Δv，单位 = 平面速度单位）。有效上限 = `min(AimMaxSpeed, dvBudget)`；
  瞄准的"力度 → 速度"映射改成 `speed = AimMinSpeed + (dvBudget - AimMinSpeed) * power` —— 满力不再是 55，而是这一关给你的数。
- **为什么这么做**：现在满力 55 一按到底，很多关根本不必借力（扫掠里 L3/L4 的解正是 `power=1.00`）。
  把预算压到"刚好够一条不太刁的航线"，弹弓才重新变成正解。
- **刹车模式上线后**：两次点火（加速 / 反推）**共享同一个预算** ⇒ 刹车要花掉你一半的 Δv，
  "省着打" 从口号变成算术。
- **UI**：HUD 上一条 Δv 条（还没做，见 S3.9.2 的表格），拖动时实时显示"这一次点火要花多少"。

##### S3.9.2d 刹车模式的分配比例（实测定的，不是拍的）

`BrakeShare` = **0.75**（点火拿 3/4，剩下的 1/4 留给后半程反推），由 `tools/level-sweep.mjs --brake` 实测确定：

| 分配 | 结果 |
|---|---|
| 0.5（原方案"一半加速一半刹车"） | 外圈转移**全部打不到**：L3~L6 成功率 0%（峰值距离从 700 掉到 ~130）|
| **0.75（采用）** | L1 6.3% / L2 10.4% / L4 2.6% / L6 4.2%；L3、L5 仍是 0（深空转移要全程点火）|
| 1.0（= 惯性滑行） | L1 4.2% / L2 6.3% / L3 2.1% / L4 2.9% / L5 2.1% / L6 35.4% |

**结论**：两种剖面是**两种战术**，不是"升级"关系 —— 刹车模式让近程关（L1/L2）更容易、深空关（L3/L5）更难。
所以 `Test/LevelDataTest` 的判据是"**任一剖面有解**"（先惯性、再密网格、最后刹车，三级升级），
玩家在 HUD 上自己选（两段式「惯性 / 刹车」）。
- **判据**：`Test/LevelDataTest` 与 `tools/level-sweep.mjs` 的扫掠**必须按 `dvBudget` 采样**（不能再按全局 55），
  每关在预算内仍要有解；某关扫不过就调该关的预算（这是"这一关给你多少燃料"的设计参数）。

##### S3.10.1 交互分区（**一个全屏层，按落点判模式**）

⚠️ **不要开两个全屏触摸层**（一个"瞄准"一个"观察"）：AGENTS 硬约束 4 已经踩过 —— 全屏 + `swallowTouches`
的层会独占点击，两层叠加必定互相吞。正确做法：**只留一个全屏层**，在 `onTapBegan` 里按**按下点**决定这一次拖动是什么模式：

| 按下点 | 模式 | 拖动效果 | 松手 |
|---|---|---|---|
| 距探测器 ≤ `R_aim`（建议 ≈150 view px，约屏宽的 1/4） | **瞄准** | 相对拖动（沿用 S2 的相对模型）：出预测线 + Δv 读数；**时间冻结** | **不发射** ⇒ 进入 `Armed` 态 |
| 其他任何地方 | **观察** | 自由相机：绕当前焦点转（方位/俯仰，俯仰沿用 `CameraTiltMin/Max` = 20–60°）| 停在松开时的机位 |

- **双指捏合** = 观察距离（`CameraMinDistance..CameraMaxDistance` 之外再放宽？见 §S3.10.3 的相机参数）；
- **点一下天体 / 探测器**（不拖动）= 把观察焦点切到它（焦距按它的半径自动适配）；
- **观察态时间照常走**（待机时钟：探测器绕地球转）；**一旦进入瞄准（含 Armed）就冻结** —— 与 S3.9.4 的规则一致；
- 时间流按钮（加速/回退）在观察态**保留**（"一边看一边等窗口"正是这个设计的用途）。

- `Armed` = "已经瞄好了，等着按发射"：**预测线常显**（不再跟手指）、Δv 读数定格、**屏幕上一个「发射」按钮**。

- **`Armed` 态下的继续操作**（建议，待用户确认）：

  - 在**其他地方**拖 = 继续观察，**预测线保持**（因为它已经画出来了）；
  - 「发射」按钮 = 立刻 `launch()` 进入 `Flying`；另有「取消」= 回观察态（清掉预测线）。
- ⚠️ 实现纪律：按钮**只在 `Armed` 态 `setEnabled(true)`**，其它时候隐藏 + **断触摸**（硬约束 4）；

#### S3.8 · 摄像机升级：出发前自由查看 + 飞行中电影化运镜（2026-09-26 用户提出）

> **用户原话**："恐怕要调整调整游戏的摄像机？我打算改为玩家可以随意 3D 的查看卫星，比如在出发前的时候。
> 出发后除了自由查看，摄像机也可以像电影一样做几个好看的飞掠视角，以及特写。" 同轮反馈：当时那一版的**尺度仍然很怪**，

##### S3.8.1 出发前：自由 3D 查看（Inspection 模式）

- **入口**：右下角一颗「查看」按钮（切到查看模式；再点回首「瞄准」）。
  ⚠️ 触摸冲突：瞄准层是全屏 `swallowTouches` 的（AGENTS 硬约束 4），查看模式必须**接管同一个全屏层**并互斥开关，
  不能两个层同时开（否则"拖不动 / 点不中"）。
- **操作**：单指拖 = 绕当前焦点轨道旋转（方位角/俯仰角）；双指捏合或右侧竖直滑杆 = 距离；
  点行星 / 点探测器 = 把焦点切到它（焦距自动适配它的半径）。
- **实现**：把 `CameraRig` 的"自动取景"参数化 —— `CameraFrame` 已经是 `{eye, target}`，
  自由相机只需要**直接写**这两个量（俯仰限制沿用 `CameraTiltMin/Max`，距离沿用夹紧区间），
  然后照旧走 `prepareCamera/projectPrepared`（预测线与到达环会自动跟上，不用改渲染层）。
- **冻结语义**：查看模式下行星仍停在 `t0`（D2 的冻结模型不变），所以"查看"是纯观察，不影响物理。

##### S3.8.2 飞行中：电影化运镜（Director）

- **镜头表**：起飞特写（贴探测器 8–12 单位）→ 拉开全景（整条航线）→ **每颗航点的飞掠特写**（探测器掠过时贴过去 15–30 单位）
  → 结局远景（终章接管）。每条镜头 = `{时机, 焦点, 距离, 俯仰/方位, 过渡时长}`，用缓动插值。
- **触发**：按**事件**而不是按时间 —— 起飞、进入某颗行星的 X 单位、离开、命中、出界（事件在 `Game.ts` 已经都有：
  `coreLaunch` / 逐帧距离 / `goalIndex` / `outcome`）。
- **可打断**：玩家一点「查看」就接管（自由相机），松手回到自动运镜（或停在手动视角直到再点"自动"）。
- **不做**：电影感晃动、景深、镜头光晕 —— 归 S3.4（后处理）；本轮只做机位与运镜。

##### S3.8.4 建模侧的交付约定（给用户的提示词用）

- **文件名不变**（`Planet_*.glb`），代码零改动；
- **本体半径 ≈ 1.0**（模型单位）：`displayRadius` 的换算表 `MODEL_RADIUS` 是按"scale=1 时外接半径 ≈1"标定的；
  若半径变了，Agent 会用 `Test/ModelCalibProbe` 重新标定（别自己换算，容易错）；
