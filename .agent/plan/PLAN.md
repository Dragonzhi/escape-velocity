# 实施计划

> 唯一事实来源是 [`docs/开发手册.md`](../../docs/开发手册.md)。本计划只细化"按什么顺序做、怎么验收"，不另立技术说法。
> 进度与证据见 [`PROGRESS.md`](./PROGRESS.md)。

## 目标

按开发手册交付一个可玩、可 Web 导出、通过验收的竖屏六关物理规划小游戏。

## 范围

**做**：竖屏、单指、六关、一次性发射、引力弹弓、结算与关卡选择、Web 导出。
**不做**：真实轨道力学、自由漫游沙盒、多人、复杂后处理管线。

|---|---|---|---|---|
| L1 | 出发 · **操作**（无引力） | 无引力体；一颗目标天体「月球方向」 | 命中目标（tolerance ≈3） | 现 L1 的直飞骨架 + `Sphere.gltf` 染灰当月球 |

##### S3.6.3 三星评价（0.5 天）

- **判定（纯函数，可单测）**：`StarResult { mission, precision, speed }`
  - 任务 ★ = `ResultKind === 'success'`
  - 精度 ★ = 与「关键天体」的最近距离 ≤ `stars.precisionDist`（关键天体默认取目标；可用 `focusIndex` 改成飞掠体）
  - 速度 ★ = 末速度 ≥ `stars.minSpeed`
- **数据**：`LevelDef.stars?: { precisionDist: number; minSpeed: number; focusIndex?: number }`（缺省 = 该关只算任务星）。
- **接入点**：`Game.ts` 飞行结束时（`flight.points` 已按每步采样 ⇒ 逐点算与关键天体的距离；末速度取 `flight.state.vel`）。
- **存档（关键，必须向后兼容）**：`Progress` 扩成 `{ unlocked: number; stars?: number[] }`，文件两行：
  ```
  unlocked=3
  stars=3,2,0,1,0,0
  ```
  - 旧档没有 `stars` 行 ⇒ 全 0，**不整份作废**；解析失败同样归 0。
  - `stars` 保持**可选**字段 ⇒ 现有 `saveProgress({ unlocked: 3 })` 调用与 `ProgressTest` 的格式断言不用改。
  - 每次结算取 `max(旧星, 新星)`（与解锁一样“只增不减”）。
- **UI**：结算面板加一行三颗星（暗/亮）+ 三行小字（显示**原始数值**：最近距离、末速度 —— 玩家要知道差多少）；
  选关面板按钮上显示已得星数（`★★☆`）。
- **验收判据**：① 单测：判定纯函数（构造三种结果）+ 存档往返 + **旧档兼容**（只有 `unlocked` 行时读成 0 星）；
  ② 截图：三种星级各一张 + 选关显示星数；③ 日志：`stars=...` 落盘。

##### S3.6.4 时间轴（发射时机，0.5–0.7 天）

- **物理层**（两行改动）：`SimOptions` 增加 `t0`；`simulate` 内部从 `t0` 起累加时间
  （`bodyPositionAt` / `accelerationAt` / `collisionIndex` 本来就吃 `t`，核心不用动）。
  **预测线与真实飞行必须共用同一个 `t0`** —— 否则又会出现「看到的 ≠ 飞到的」。
- **游戏侧**：`GameCore.t0`；`coreLaunch` 把 t0 传进 `simulate`；`syncBodies(t0)` 在拖动时实时更新行星位置。
- **UI**：底部「发射窗口」滑杆（轨道 + 滑块 + 当前相位读数）；拖动时行星跟着走，玩家**看得见**自己改了什么。
  ⚠️ **触摸分层**：瞄准层是全屏 `swallowTouches`；滑杆层必须建在它**之后**（画在上面、先拿触摸），
  且只在 `Aiming` 且该关有 `timeWindow` 时开触摸 —— 隐藏/飞行/结算时必须断触摸（`AGENTS.md` 硬约束 4）。
- **关卡开关**：`LevelDef.timeWindow?: { span: number }`（L1–L3 不给 ⇒ 滑杆不建，行为与现在完全一致）。
- **验收判据**：① 单测：同一初速度、不同 `t0` ⇒ 轨迹不同；同一 `t0` ⇒ 预测线与真实飞行逐点一致；
