# L1 呈现层修复计划（S5.1）

> 2026-09-27 立项。用户原话：「先别管 L2 到 L6 了，先把当前的 L1 真的做好！现在 L1 完全不能把玩啊。」
> 三条症状：① 2D 下 Δv 给的是 0、探测器离地球那么远；② 3D 下完全看不到地球；
> ③ 发射后视角距探测器太近、屏幕被占满，探测器建模也看不全。
> **本轮不动模型**（用户明确：「先不碰模型」）—— 只修取景、读数与尺度。

---

## 1. 症状与根因（都已用代码定位，非猜测）

### ① 3D 里看不到地球

`game/Game.ts` 的取景锚点：

```ts
export function anchorBodyIndex(bodies: Body[]): number {
	let best = -1;
	for (let i = 0; i < bodies.length; i++) {
		const b = bodies[i];
		if (b.orbitRadius !== 0) continue;      // ← 只认"不绕转"的天体
		if (best < 0 || b.gm > bodies[best].gm) best = i;
	}
	return best;
}
```

S5 归正后 L1 的天体是：太阳 `orbitRadius = 0`、gm 72000；地球 `orbitRadius = 80`。
⇒ **锚点从地球变成了太阳**（该函数上方的注释还写着「L1 是地球 2600」，那是归正前的旧数据）。

锚点一错，`framingPoints()` 就把太阳塞进取景集合，而 `CameraRig.computeFit()` 取的是
**包围盒中心**：探测器 (0, 80.1) 与太阳 (0, 0) 的包围盒中心 = (0, 40)，跨度 80 单位。
`CameraFramingBudget = 240` 的预算检查救不了它（80 < 240 ⇒ 含太阳那一组**永远被采用**），
于是相机距离被解到 ~80 单位，地球（轨道半径 80）落在画面边缘、太阳在画面中心 ——
玩家看到的是一颗遥远的太阳，地球当然"完全看不到"。

### ② 发射后被探测器占满屏幕

`game/Game.ts` 的慢动作判定：

```ts
const threshold = Math.max(b.radius * SlowMoRadiusFactor, SlowMoFloorDist);   // 5 / 8
```

这是**世界单位的固定地板 8**。归正前 L1 的地球半径 1.76、探测器轨道 10，8 是合理值；
归正后 L1 的地球物理半径 **0.0034**、月球 **0.00093**，乘 5 后统统落到地板 **8** ——
而 L1 的整个世界只有 **0.6 单位宽**。⇒ **整段飞行 100% 处于慢动作特写**，
且特写分支把 `radii` 换成 `near.radius`（0.0009），
`CameraRig` 的逐点半径求解据此把距离解到近乎 0。

### ③ Δv 恒显示 0 / 探测器"离地球远"

- `init.ts` 只在**建关时**调了一次 `aim.setBurnInfo(0, def.dvBudget)`，
  之后没有每帧刷新 ⇒ 读数永远停在初始值。
- `Hud.ts`：`'Δv ' + burn.toFixed(1) + ' / ' + budget.toFixed(0)` ——
  L1 的预算 0.35 被 `toFixed(0)` 打成 `0`，和 burn 的 0 撞在一起，看起来像"这一关没给预算"。
- 2D 图钉用固定像素（`Tuning.PLAN_PIN_PX.probe = 11`）。L1 的 2D 视野半径 0.2256、
  scale ≈ 1045 px/单位 ⇒ 11 px ≈ **0.0105 单位**，而探测器真实视觉半径 0.0015 ——
  **图钉被放大了 7 倍**，"位置感觉不对"有它一份。
- "离地球远"本身是**真实比例的必然**：探测器轨 0.1 vs 月球轨 0.2056，只差 2 倍。
  这是用户拍板的真实尺度，不能为了观感改物理；能改的是**让地球在画面里足够大**（见第 3 节）。

## 2. 修复项（四项，全部集中在 L1 路径）

### R1 锚点选择：认"宿主链"，不认"不绕转"

`game/Game.ts` · `anchorBodyIndex`

改成：**候选 = 有别的天体绕着它转（作为 `Body.host` 出现）、或本身不绕转且 gm 最大**的那个；
且优先取"本关探测器实际围绕的对象"。判据用纯函数表达，保持可单测：

- L1：月球 `host = 地球` ⇒ 地球是宿主 ⇒ **锚点 = 地球**；
- L2–L6：没有 `host` 链，退回原逻辑（太阳）。

同步删掉/改掉那句「L1 是地球 2600」的过时注释，并把 `Test/GameTest` 补一条
"L1 的锚点是地球"的断言（现在这条是错的，测试居然没抓到——因为断言写的是旧期望）。

### R2 慢动作阈值按关卡尺度归一

`game/Game.ts` · `slowMotionBody` + `game/Tuning.ts`

阈值从"世界单位固定地板 8"改为**每关一个地板**（进 `LevelRuntime`）：

- `slowMoFloor`：L1 = `0.05`（月球轨 0.2056 的 1/4）、L2–L6 保持 8；
- 天体半径乘数仍取 5（L1 月球 0.00093×5 = 0.0047，取地板 0.05 ⇒ 接近月球 0.05 内才慢动作）。

效果：L1 只在**真正接近月球**时进特写，而不是全程特写。
`Test/GameTest` 已有 slowmo 断言，需要按新阈值更新。

### R3 L1 的地月系视觉半径 + 相机夹紧

`game/Tuning.ts` · `BODY_VISUAL_RADIUS` + `LEVEL_RUNTIME`

- L1 专用视觉半径：地球 **0.06**（= 地月系宽度的 10%）、月球 **0.02**、探测器维持 0.0015。
  现在地球 0.025 在 0.6 单位宽的世界里只占 4%，3D 里几乎看不见。
  ⚠️ 只改视觉，不改 `Body.radius`（物理仍 0.0034）—— 分层不变。
- L1 的 `cameraMax`：3 → **0.9**。现在上限 3 会让"装下整个地月系"的解偏大；
  0.9 刚好覆盖月球轨 0.2056 + 容差 0.02 再加余量，又不会把地球缩太小。
  `cameraMin` 保持 0.02。

### R4 Δv 读数每帧刷新 + 小数格式 + 2D 图钉归一

三处：

1. `init.ts` 主循环：每帧 `aim.setBurnInfo(game.burnNow(), def.dvBudget)`
   （需要给 `Game` 接口加一个 `burnNow()` —— 或直接用已有的 `aimInfo()` 之类的读取；
   没有就加一个三行的 getter）。静止态也会显示当前档位，不再永远是 0。
2. `Hud.ts` · `setBurnInfo`：预算 < 1 时用 `toFixed(2)`，
   L1 显示 `Δv 0.00 / 0.35` 而不是 `Δv 0.0 / 0`。
3. `PlanView` 图钉半径：从"固定像素"改为
   **`max(固定像素, 真实视觉半径 × scale)`**，让 L1 的探测器图钉不再被放大 7 倍。
   太阳/行星同理（L2–L6 视野大，视觉半径 × scale 很小，仍取固定像素 ⇒ 行为不变）。

## 5. 风险

1. R1 改锚点会影响 `slowMotionBody`（它接收 `anchor` 参数排除锚点）——
   必须同步验证"掠过月球仍然触发慢动作"。
2. R3 把地球视觉放大 2.4 倍后，`Scene` 的 `scale = displayRadius / k` 会跟着变，
   `Test/SceneProbe` 若有尺寸断言需要同步。
3. R4 每帧 `setBurnInfo` 会重建 Label 文本 —— 必须确认它只在**文本变化**时才
   `setText`（否则每帧创建字符串有代价）。
